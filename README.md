# Crazyflie: облёт препятствий

Дрон взлетает на 30 см и летит вперёд. Если впереди препятствие, он зависает,
осматривается дальномерами и решает, как его облететь: слева, справа или сверху.
Облетев, пролетает ещё 60 см (`after_obstacle`) и садится. Если препятствий нет,
садится, пролетев `goal_distance` метров.

## Что нужно

- Crazyflie 2.x (или 2.1 / 2.1+)
- **Multi-ranger deck**: дальномеры вперёд, назад, влево, вправо и вверх
- **Flow deck v2**: держит позицию и высоту, нижний дальномер
- Crazyradio PA / 2.0
- Python 3.8+ и `pip install cflib`

## Файлы

| Файл | Что делает |
|---|---|
| `avoidance.py` | Вся логика облёта (без cflib). Все настройки лежат в `Config` |
| `fly.py` | Запуск на настоящем дроне |
| `simulate.py` | Симулятор для проверки логики без дрона |
| `check_drone.py` | Проверка: видно ли радио, дрон и оба модуля (без взлёта) |
| `sensors.py` | Показывает расстояния с датчиков вживую (без взлёта) |
| `explore.py` | Режим исследования: дрон сам летает по комнате и строит 2D-карту |
| `explorer.py`, `mapping.py` | Логика исследования и карта (без cflib) |
| `explore_sim.py` | Симулятор режима исследования |
| `scan_by_hand.py` | 2D-карта без полёта: крутишь дрон рукой в нескольких точках |
| `led_builtin.py` | Встроенные лампочки с клавиатуры |
| `update_firmware.py` | Обновление прошивки на официальную |

## Запуск

Сначала проверь логику в симуляторе:

```bash
python3 simulate.py
```

Если стоит `matplotlib`, рядом появятся картинки траекторий `sim_*.png`.

Потом на дроне:

```bash
python3 fly.py
```

Если адрес дрона другой:

```bash
CFLIB_URI=radio://0/80/2M/E7E7E7E7E7 python3 fly.py
```

**Ctrl+C** в любой момент (даже во время взлёта): дрон плавно садится.

Если сразу после взлёта боковой датчик показывает меньше 10 см, программа считает его
закрытым или сломанным, пишет об этом и не облетает в ту сторону. Если так показывает
передний датчик, дрон сразу садится.
Если перевернуть дрон вверх ногами, моторы сразу выключатся (аварийная остановка);
при следующем запуске `fly.py` сам перезагрузит дрон.

## Как выбирается сторона облёта

Когда впереди ближе `obstacle_dist` (0.5 м), дрон зависает, делает 5 замеров и ставит
каждому варианту оценку:

- **слева / справа**: сколько свободного места в эту сторону (не больше 2 м).
  Сторона, которая ведёт обратно к исходной линии, получает бонус `+0.3`.
  Если места меньше `min_side_room`, вариант отбрасывается.
- **сверху**: сколько можно подняться (до потолка минус запас и не выше `max_height`)
  минус небольшой штраф `up_penalty`, потому что облёт сверху дольше.

Выбирается вариант с самой большой оценкой. Если он не сработал (сбоку стена,
ушли дальше `max_shift` от линии, упёрлись в потолок), дрон пробует следующий.
Если вариантов не осталось, он садится.

Примеры из симулятора:
- колонна, слева близко стена → облетает **справа**
- узкий коридор, поперёк низкий ящик → облетает **сверху**
- широкая стенка → пробует слева, потом справа, потом **сверху**
- две колонны подряд → слалом
- тупик → **посадка**

## Ограничения и советы

- Дальномеры смотрят узким лучом (~27°). Тонкие предметы (ножка стула, провод)
  и стекло они могут не увидеть.
- Flow deck измеряет высоту **над тем, что под ним**. Когда дрон пролетает над
  ящиком, оценка высоты «проседает» и дрон немного поднимается. От потолка его
  защищает верхний дальномер, но лучше тестировать в комнате с высоким потолком.
- Flow deck плохо работает над однотонным/блестящим полом. Положи ковёр или что-то
  с текстурой.
- Дрон не поворачивается (yaw не меняется), назад он не смотрит.
- Первые полёты делай на маленькой скорости (`forward_speed = 0.15`) и в просторной
  комнате.

## Лампочка по пробелу

Светодиод подключается к **левому** разъёму (пин 1 — у квадратной площадки, ближе к носу):

| Пин | Сигнал | Куда |
|---|---|---|
| 9 | IO_4 (PC12) | резистор 100–220 Ом → длинная ножка светодиода (+) |
| 10 | GND | короткая ножка светодиода (−) |

Без резистора светодиод может сгореть вместе с выводом дрона.

Обычная прошивка не умеет управлять этим пином, поэтому дрон надо один раз прошить
приложением из папки `led_app`:

```bash
brew install --cask gcc-arm-embedded
cd ~/Desktop
git clone --recursive https://github.com/bitcraze/crazyflie-firmware.git
cd ~/Desktop/crazyflie/led_app
source ../.venv/bin/activate
make -j
make cload
```

Перед `make cload` переведи дрон в режим загрузки: выключи его и зажми кнопку
включения на 3 секунды (синие огоньки мигают).

Потом:

```bash
python3 led_space.py
```

**Пробел** — включить/выключить лампочку, **q** — выход.

## 2D-карта (режим исследования)

Дрон взлетает на 40 см, поворачивается на месте и осматривается всеми четырьмя
боковыми дальномерами. Потом летит туда, где на карте больше неисследованного,
каждые 1.5 м снова осматривается. Через 3 минуты (`duration`) садится.

```bash
python3 explore_sim.py   # сначала в симуляторе: sim_map.png
python3 explore.py       # на дроне: map.png и points.csv
```

На карте белое — пусто, чёрное — стены, серое — не исследовано. `map.png`
обновляется каждые 2 секунды, его можно держать открытым в VS Code.
`points.csv` — облако точек стен (x, y в метрах от точки взлёта).

Ставь дрон посередине комнаты, на пол с узором. Настройки — в `ExploreConfig` (`explorer.py`).

Защита в режиме исследования та же, что в `fly.py`: подключение не зависает, зависшие
датчики (все по нулям) и блокировка после аварийной остановки лечатся автоматической
перезагрузкой дрона, перевернули вверх ногами — моторы сразу выключаются, пропала связь
или дрон потерял положение — садится. Карта сохраняется в любом случае.

### Карта без полёта

Если Flow deck не работает, можно построить карту рукой: сними Flow deck,
поставь дрон на книгу (~40 см над полом), запусти `python3 scan_by_hand.py`
и медленно поворачивай книгу на полный оборот в нескольких точках комнаты.
Координаты точек (x y в метрах) меряешь рулеткой.
